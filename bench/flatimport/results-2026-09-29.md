# Host import experiment — 2026-09-29

Apple M3 Pro, darwin/arm64, Go 1.26.5. Each sample is five imports;
three samples per case. Each import has 64 threads and 10,240 events.
Median of each metric is calculated separately. Time range is the range of
sample means, not per-import latency. Allocation bytes are cumulative, not peak RSS.

The machine was shared and background system work caused substantial variation
(particularly Claude's first baseline sample). Total-time differences are not
strong evidence of an end-to-end speedup. The phase measurements consistently
place most of the work in SQLite. FlatBuffers cannot remove the original JSONL
parse on first import, and constructing the cache adds work and allocation.

An existing binary cache reduces read/materialization time, but normalized JSON
is already substantially cheaper to read than provider JSONL. That control
separates pre-parsing from the choice of serialization. These measurements do
not justify replacing the import path with FlatBuffers for first-sync speed.
Profile the SQLite import/write path next; measure RPC serialization separately
if the actual target is syncing threads to the phone.

Binary cache sizes: Claude 5,673,776 bytes versus 5,937,520 source JSONL bytes;
Codex 5,510,064 versus 6,123,568. These are different representations of the same
conversation events: the cache omits provider bookkeeping and is not a wire-size
comparison. No compression/network/Swift decoding was measured.
